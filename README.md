# omsk-together

Проект для хакатона, автоматизирующий обработку массовых обращений граждан с помощью искусственного интеллекта.

Система берет на себя всю рутину по чтению сотен тысяч сырых жалоб: фильтрует спам и эмоции, обезличивает персональные данные (согласно 152-ФЗ) и выдает сухую аналитическую выжимку проблемных зон муниципалитетов. Снижает время реакции администрации на инциденты с нескольких недель до считанных минут.

---

## Обзор

Проект работает по архитектуре изолированных микросервисов, чтобы максимизировать скорость обработки тяжелых таблиц и оптимизировать потребление вычислительных ресурсов оборудования:

* **core-service**: backend-логика для быстрого парсинга гигантских Excel-таблиц и генерации итоговых файлов.
* **llm-service**: ИИ-модуль, отвечающий за классификацию и генерацию саммари.
* **frontend**: легкий клиентский веб-интерфейс.

---

## Возможности

* Многократное сокращение времени анализа: большой массив данных обрабатывается за ~10 минут (вместо ручных недель или ожидаемых 40 минут).
* Двухуровневая AI-система: классификатор (`S1lv570/RuBERT-Digital-Breakthrough`) моментально отсеивает мусор, а языковая модель (`Qwen/Qwen3-8B`) делает емкую выжимку, не перегружая железо.
* Встроенное обезличивание: нейросеть автоматически скрывает все персональные данные, защищая ведомство от юридических рисков.
* Мульти-форматный экспорт: генерация готового к скачиванию ZIP-архива, содержащего Excel-таблицы (Топ-3 критичных, Топ-10 общих) и готовый глобальный отчет `.docx` для совещаний.
* Полная локальность и безопасность: сервис запускается изолированно, никуда не обращается и работает на доступном оборудовании (протестировано на 16GB VRAM).
* Асинхронное взаимодействие через Redis и единственный REST API эндпоинт для простой интеграции в любые системы (боты, личные кабинеты, сайты). Веб-интерфейс, по сути, опционален

## Установка и запуск

### Требования

* [Java 25 (Corretto)](https://docs.aws.amazon.com/corretto/latest/corretto-25-ug/downloads-list.html)
* [uv (Пакетный менеджер Python)](https://docs.astral.sh/uv/getting-started/installation/)
* Запущенный локальный сервер Redis (на порту 6379)

### 1. Предварительная подготовка

Распакуйте архив `omsk-together.zip` в удобную директорию. Из архива появится папка `omsk-together-main`.
Откройте терминал (в Windows используйте PowerShell) и перейдите в папку проекта:

```bash
# Для Windows:
cd <путь\до\omsk-together-main\>
# Для Linux:
cd <путь/до/omsk-together-main>
```

#### Сборка Core-сервиса (Java)

Перейдите в папку `core` и соберите проект:

```bash
cd core
mvn clean package
```

#### Настройка LLM-сервиса (Python)

После успешной сборки Java-части, перейдите в папку `llm`:

```bash
cd ../llm
```

Перед установкой зависимостей необходимо подобрать правильную версию индекса для PyTorch. Проверьте версию вашего драйвера видеокарты командой:

```bash
nvidia-smi
```

Сверьте версию драйвера с таблицей ниже:

| Версия драйвера | Индекс для PyTorch |
| --- | --- |
| 570.x и выше | 128 |
| 560.x | 126 |
| 550.x | 124 |
| 527.x | 121 |

**Важно:** По умолчанию проект настроен на индекс `128`. Если ваша версия отличается, откройте файл `pyproject.toml` в любом текстовом редакторе, пролистайте в самый низ и найдите строку:
`url = "https://download.pytorch.org/whl/cu128"`
Измените число в конце ссылки на то, которое подошло вам по таблице (например, `cu124`). Сохраните файл.

Вернитесь в терминал и запустите установку зависимостей:

```bash
uv sync
```

Установите модели в папку resources:

```bash
uv run hf download S1lv570/RuBERT-Digital-Breakthrough --local-dir resources/RuBERT
uv run hf download Qwen/Qwen3-8B --local-dir resources/Qwen
```

Скопируйте файл .env.example как .env и задайте значения для REDIS_HOST, если Redis стоит не локально на вашей машине

```env
RUBERT_PATH=resources/RuBERT
QWEN_PATH=resourses/Qwen
REDIS_HOST=localhost # заменить на нужный айпи/домен (без указания протокола)
REDIS_PORT=6379
```

Дождитесь полной загрузки библиотек и весов моделей.

#### Настойка веб-интерфейс (Python) (опционально)

> *Внимание: по умолчанию веб-сервер запущен на хосте `0.0.0.0` и доступен извне локальной сети (необходимо для проведения live-демонстрации проекта).*

Если вы хотите запустить интерфейс без доступа извне, откройте файл `web_ui.py` в любом текстовом редакторе, пролистайте в самый низ и найдите следующие строки:

```python
demo.launch(
    server_name="0.0.0.0",  # noqa: S104
    server_port=80,
    max_file_size="10gb"
)
```

Замените строку `"0.0.0.0"` на `"localhost"`, сохраните изменения и закройте файл

---

### 2. Запуск сервисов

Для запуска системы потребуется открыть **три разных терминала**. Не закрывайте их в процессе работы, чтобы не остановить выполнение процессов (в Linux можно использовать `tmux`).

**Терминал 1 (Запуск Java Backend):**
Перейдите в папку `omsk-together-main/core` и выполните команду (целиком одной строкой):

```bash
java -Xms8G -Xmx8G -XX:+UseZGC -XX:+AlwaysPreTouch "-Djdk.xml.maxGeneralEntitySizeLimit=0" "-Djdk.xml.entityExpansionLimit=0" "-Djdk.xml.totalEntitySizeLimit=0" -jar target/core-0.0.1-SNAPSHOT.jar
```

**Терминал 2 (Запуск AI-воркера):**
Перейдите в папку `omsk-together-main/llm` и запустите нейросетевой модуль:

```bash
uv run main.py
```

**Терминал 3 (Запуск Frontend UI):**
Убедитесь, что у вас отключены прокси/VPN. В папке `omsk-together-main/llm` запустите веб-интерфейс:

```bash
uv run web_ui.py
```

### 3. Использование

После успешного запуска всех сервисов, откройте браузер и перейдите по адресу:
**[http://127.0.0.1:7860](http://127.0.0.1:7860)**
